# 폼체커 (FormChecker)

카메라로 스쿼트 횟수를 세고, 자세가 어긋나면 화면과 소리로 알려주는 안드로이드 앱입니다.
**온디바이스 추론**이라 네트워크 없이 동작합니다.

폰을 세워두고 몇 걸음 떨어져 쓰는 앱이라, 화면에 무엇을 띄우고 무엇을 소리로 말할지가
이 프로젝트의 설계 대부분을 차지합니다.

---

## 지금 되는 것

**측정**
- 스쿼트 자동 카운팅 (기준 자세를 잰 뒤부터)
- 자세 판정 7종 — 앉은 깊이 · 상체 숙임 · 뒤꿈치 들림 · 무릎이 발끝을 넘음(측면) /
  무릎 모임 · 무릎 벌어짐 · 좌우 쏠림(정면)
- **촬영 방향(정면/측면) 자동 판별** — 사용자가 고르지 않습니다
- 준비 자세 점검 5종(방향 · 무릎 펴기 · 발 간격 · 발끝 방향 · 좌우 균형)
- 스켈레톤 오버레이, 전면/후면 렌즈 전환
- 소리 신호 — rep 끝에 한 번(인정/경고), 카운트다운 틱

**기록**
- 홈 대시보드 — 오늘의 목표와 진행률, 이번 주 7일 막대그래프, 주간 합계
- 추정 소모 열량 — 선택한 날 하루치 + 이번 주 합계
- 운동 결과 — 총 횟수 / **확인한 횟수** / 피드백 횟수, 동작별 기록, 자세 피드백 문장
- 기록 목록 — 날짜별로 묶어 표시, 삭제

**안내**
- 설치 첫 실행 온보딩 4쪽 → 첫 운동 전 측정 준비 확인 → 동작 예시 GIF → 화면별 코치마크
- 설정에서 다시 보기

**설정**
- 하루 목표 횟수(기본값 없음), 기준 자세 준비 시간, 신체 정보, **자세 기준 완화**

## 화면 흐름

```
Splash ─▶ (첫 실행) Onboarding ─▶ Home ─┬─▶ Workout ─▶ SessionSummary
                                        ├─▶ History ─▶ SessionSummary
                                        ├─▶ Settings
                                        └─▶ (개발용) WorkoutLab · Capture
```

`Workout`(사용자용)과 `WorkoutLab`(개발·검증용)은 **같은 ViewModel을 공유**합니다 —
동작은 같고 표시만 다릅니다. 판정 로직을 화면에 두지 않아 두 화면이 다른 답을 낼 수 없습니다.

## 어떻게 판정하나

```
CameraX  ─▶  RTMPose-s Halpe26 (LiteRT, 192×256)  ─▶  키포인트 26개
                                                        │
                        기준 자세 3초 측정 ◀─────────────┤  다리 길이·대퇴/정강이 비율,
                        (촬영 방향 다수결)                │  촬영 방향, 정규화 분모
                                                        ▼
                                  프레임 특징 ─▶ rep 상태머신 ─▶ 판정
                                  (각도·거리비)   (하강/최저점/상승)   프레임 단위 5종
                                                                    rep 단위 2종
```

**규칙 몇 가지**

- **기준 자세를 다 잰 뒤에만 카운팅합니다.** 걸어가며 자리를 잡는 동안 유령 rep이 세어지던
  문제 때문입니다. 막는 대신 왜 안 세는지 숫자 바로 아래에 알립니다.
- **깊이 부족과 무릎–발끝은 rep 단위**입니다. 하강은 `STANDING → SHALLOW → PARALLEL`을
  지나므로, 프레임마다 말하면 *아직 내려가는 중인 사람에게 "덜 앉았다"* 고 하는 것이 됩니다.
- **뒤꿈치가 뜨면 깊이 부족을 말하지 않습니다.** 올바른 깊이는 "뒤꿈치가 뜨지 않는 범위까지"라
  둘이 함께 뜨면 서로 반대인 지시가 됩니다.
- 화면 피드백은 항목당 2초 붙잡고 **도착 순(새 것이 위)** 으로 쌓입니다 — 최저점에서 난
  경고를 다 올라온 뒤에 읽을 수 있어야 합니다(상승 p95 1,171ms).

## 이 저장소의 규칙

이 프로젝트에서 반복해서 값을 치른 것들입니다.

**판정보다 근거** — 임계값마다 `ThresholdOrigin`을 붙이고, 왜 그 값인지·무엇이 미검증인지를
KDoc에 실측 수치로 남깁니다. 그럴듯하지만 아무것도 잡지 못하는 임계값을 여러 번 실측으로
걷어냈습니다.

**틀린 답보다 없는 답** — 판정할 근거가 없으면 `null`을 냅니다. 깊이의 각도 대체 경로를
제거한 것이 그 예입니다(항상 "충분히 깊다"고 답해 경고가 영원히 안 떴습니다).

**점수 대신 사실** — `form_score`는 항상 null이고 `checked_count`/`warned_count`로
대체했습니다. 경고 종류에 가중치를 매길 근거가 없고, 숫자 하나로 뭉치면 무엇을 고쳐야
하는지도 함께 사라집니다.

**못 본 것을 반드시 말한다** — 결과 화면이 판정하지 못한 항목을 밝힙니다. 말하지 않으면
"피드백 없음"이 "전부 괜찮다"로 읽힙니다.

**분모를 의심할 것** — 정규화 실패가 반복해서 나왔습니다. 측면에서 발 길이·어깨폭·힙폭은
원근으로 압축되고, 발목 간격은 두 발이 겹치면 무너집니다.

## 임계값 상태

`SquatThresholds.kt`의 `ORIGINS`가 정본입니다.

| 묶음 | 개수 | 실측 근거 | 정의 | 잠정 |
|---|---|---|---|---|
| 자세 판정 `FormThresholds` | 16 | 6 | 6 | 4 |
| 촬영 방향 `AngleDetectionThresholds` | 3 | 2 | – | 1 |
| 준비 자세 `ReadyThresholds` | 4 | 1 | – | 3 |
| 카운팅 `CountingThresholds` | 7 | – | – | 7 |

임계값은 **자체 수집 데이터**(15세션 · 정면 12 / 측면 3)로 확정했습니다. 같은 모델·같은
기기로 찍어 domain gap이 없다는 점이 결정적이었습니다.

> **⚠ 확정된 임계값도 "정상을 오탐하지 않는가"만 검증됐습니다.** 의도적 오류 세션이 아직
> 없어 **"오류를 잡는가"는 미검증**입니다. 특히 뒤꿈치 들림은 진짜 들림의 추정치가 현재
> 임계값보다 낮아, 임계값 문제가 아니라 **측정이 둘을 못 가르는** 문제일 수 있습니다.

새 판정을 추가하기 전에 `ThresholdOrigin`을 먼저 정하세요. 근거 없는 숫자를 `PROVISIONAL`
표시 없이 넣으면 나중에 아무도 되돌릴 수 없습니다.

## 구조

```
:app           화면(Compose) · Room · DataStore · CameraX 연결
:pose-engine   추론과 판정 — 안드로이드에 의존하지 않는 순수 Kotlin 계층
```

판정을 `:pose-engine`에 격리한 덕분에 기기 없이 단위 테스트로 붙들 수 있습니다
(현재 `:pose-engine` 292개 · `:app` 98개).

**저장** — Room 4테이블(`workout_sessions` / `workout_sets` / `rep_records` /
`performance_metrics`) + `sync_status`. 스키마 v4, `app/schemas`에 export.
rep마다 **어느 기준으로 판정했는지**(기준 완화 여부·허용폭)를 함께 남깁니다 — 나중에
임계값을 재분석할 때 섞인 데이터가 되지 않도록.

**설정**은 Room이 아니라 DataStore입니다. 동기화 대상이 아니고(`sync_status`가 붙을 값이
없음), **기본값을 저장소에 두지 않습니다** — 없으면 `null`을 내고 호출부가 자기 기본값을
씁니다.

## 기술 선택

| 무엇 | 왜 |
|---|---|
| **RTMPose-s Halpe26** (LiteRT) | 발 키포인트가 있어야 뒤꿈치 들림·무릎–발끝을 계산할 수 있습니다. MoveNet(COCO 17)에는 없습니다 |
| 프리뷰 **3:4 · 화면 폭 전부** | 모델 입력이 192×256이라 letterbox 패딩이 0입니다. 16:9로 바꾸면 가로를 75%만 쓰고 정면 판정(수평 측정)의 임계값 근거가 흔들립니다 |
| **Compose + 타입 안전 Navigation** | 라우트 인자가 컴파일 타임에 검증됩니다 |
| **Room**(오프라인 1차 저장소) | 네트워크 실패가 운동 흐름을 막지 않아야 합니다 |
| **DataStore**(설정) | 읽기가 Flow여야 화면을 다시 열지 않고 반영됩니다 |
| GIF를 **플랫폼 ImageDecoder**로 | 이미지를 쓰는 자리가 하나뿐이라 이미지 로딩 라이브러리를 들일 값이 없습니다 |
| 코치마크를 **직접 구현** | 스크림·좌표·입력 차단 세 가지면 충분하고, 라이브러리는 테마 밖 색을 함께 들고 옵니다 |

버전은 검색 요약이 아니라 Maven 메타데이터를 직접 조회해서 고정합니다.

## 아직 없는 것

- **서버 동기화** — Room이 1차 저장소로 동작하고 모든 행이 `sync_status = PENDING`으로
  쌓입니다. 기록 화면이 그 수를 정직하게 배지로 보여줍니다
- **인증** — `user_id`는 nullable로 두고 나중에 마이그레이션으로 채웁니다
- **세트 개념** — rep을 연속으로 셉니다. `workout_sets`는 세션당 1행입니다
- **의도적 오류 세션** — 위의 "오류를 잡는가" 미검증 문제
- 스쿼트 외 종목 — 홈은 이미 종목 이름을 말하지 않습니다("운동 시작")
