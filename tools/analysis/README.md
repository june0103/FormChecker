# 수집 데이터 분석 도구

앱이 내보낸 세션 폴더(`session/frames/reps` × `csv/jsonl`)를 읽어, 정상 범위 임계값을
만드는 데 필요한 세 가지를 답한다.

의존성이 없다 — 표준 라이브러리만 쓴다. 촬영 현장에서 `pip install`이 필요하면 도구가
없는 것과 같다.

```bash
python check_sessions.py   <세션폴더 또는 captures 폴더>...      # 이거 쓸 수 있나
python reference_range.py  <세션폴더>... [-o reference_range.csv] # 정상 범위
python variance_split.py   <세션폴더>...                          # 정규화가 통하나
```

세션 폴더를 직접 줘도 되고, 여러 세션이 담긴 상위 폴더를 줘도 된다. 기기에서 `captures/`를
통째로 꺼내는 것이 가장 흔한 경우다.

```bash
adb pull /sdcard/Android/data/com.mist.formchecker/files/captures ./captures
python check_sessions.py ./captures
```

## `check_sessions.py` — 촬영 당일에 판단한다

이 프로젝트에서 못 쓸 데이터를 **다 찍은 뒤에** 알아차린 일이 두 번 있었다. 진행도 컬럼이
2243행 전부 빈 칸이었던 것, 하강 진행도 0~50% 구간에 표본이 하나도 없었던 것. 두 번 다
재촬영이었다. 촬영은 되돌리기가 가장 비싼 작업이므로 판단을 그 자리로 옮긴다.

세션마다 PASS/FAIL과 근거를 낸다. 통과선은 전부 실측에서 나온 값이고, "정상일 때"와
"고장났을 때" 사이에 여유를 두고 잡았다.

| 항목 | 통과선 | 고장 시 실측 | 정상 시 실측 |
|---|---|---|---|
| `frame_index` 불연속 | 0곳 | 19곳 | 0곳 |
| rep 밖 프레임 | 1개 이상 | 0개 | 254~280개 |
| 하강 전반부 프레임 | rep당 2개 이상 | 0개 | rep당 10~12개 |
| 하강/상승 길이 비율 | 0.6~2.5 | 0.34 | 1.18~1.26 |
| rep 첫 프레임 굴곡 | 15° 이하 | 55.8° | 2.4~5.3° |
| 각도별 필수 특징 채움률 | 90% 이상 | 0% | 100% |
| 극값 여유 (체류/최대간격) | 3프레임 미달이 20% 이하 | — | 3.4~5.9프레임 |
| 이상치 비율 | 35% 이하 | — | 15~25% |

마지막에 조건별 세션 수를 세어, 세션이 1개뿐인 조합을 표시한다.

실패하면 종료 코드 1이라 스크립트에 물릴 수 있다.

## `reference_range.py` — 최종 산출물

`include_in_reference = 1`인 rep의 프레임을 **단계 × 진행도 구간**(하강 5칸, 최저점 1칸,
상승 5칸)으로 나눠 특징별 백분위수(p5·p25·p50·p75·p95)를 CSV로 낸다. rep 단위 요약 특징도
같은 형식으로 낸다.

시간이 아니라 진행도로 나누는 이유는 사람마다 속도가 달라 시간으로 맞추면 같은 지점이
다른 자세를 가리키기 때문이다(설계문서 §15.1).

**진행도 방향 주의**: 하강은 0 = 선 자세, 1 = 최저점. **상승은 0 = 최저점, 1 = 기립.**
두 구간에서 방향이 반대다. "상승 0-20"은 최저점 직후를 뜻한다.

사람별 표와 합친 표를 모두 내고, 두 폭(p95−p5)의 배수를 비교한다. 합친 폭이 개인 폭보다
훨씬 넓으면 그 특징은 사람마다 다른 값이라 공통 임계값으로 쓸 수 없다. 같은 각도를 두 사람
이상이 찍어야 이 비교가 성립한다 — 한 명뿐이면 배수가 항상 1.00으로 나와 결과처럼 보이므로
아예 건너뛴다.

## `variance_split.py` — 정규화가 체형을 지웠나

목표는 사용자 자세를 정상 데이터와 비교해 리포트를 내는 것인데, 다른 사람의 범위와
비교하면 체형 차이가 "오류"로 보고된다. 갈래가 둘이다.

- 모집단 범위를 만든다 → 사람 수십 명 필요.
- 사용자마다 캘리브레이션해서 상대 편차로 판정한다 → 정규화가 체형을 지워야 성립.

이 도구는 두 번째 길이 특징별로 성립하는지 답한다. rep 단위 특징마다 **사람 내 MAD**와
**사람 간 MAD**를 재고 그 배수를 낸다. 2배를 넘으면 사람 간 차이가 사람 내 변동을 압도하는
것이라 개인 기준선이 필요하다.

체형 변수도 사람·각도별로 늘어놓는다. 여기서 확인된 것:

- **측면에서 `hip_width`·`shoulder_width`는 체형 변수가 아니다.** 좌우 간격이 카메라 축
  방향이라 원근으로 압축된다. 같은 사람 P001이 정면 0.334 / 측면 0.055로 6배 차이였다.
- **`trunk_length/legLength`는 각도에 강건하다.** P001이 정면 0.781 / 측면 0.779.
- **`femur_tibia_ratio`는 각도에 따라 7% 흔들린다** (P001 정면 1.098 / 측면 1.025). 두
  사람의 차이가 그보다 작으면 구분할 수 없다.

## 지금 데이터로 답할 수 없는 것

세 도구를 실측 세션에 돌려 확인한 공백이다.

- **사람마다 세션이 1개**다. 사람 간 차이가 "그 세션이 그랬던 것"인지 "그 사람이 원래 그런
  것"인지 갈라낼 수 없다. 사람 수를 늘리기보다 **사람마다 세션 2개**가 먼저다.
- **같은 각도를 두 사람 이상이 찍은 적이 없다** (P001 좌측면 / P002 우측면). 그래서 폭 비교와
  변동 분해가 성립하지 않는다.
- **신발이 사람과 함께 바뀌었다.** 신발 효과를 보려면 같은 사람이 신발만 바꿔야 한다.
